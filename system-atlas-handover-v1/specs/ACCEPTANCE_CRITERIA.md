# Acceptance criteria

Version 1 · 24 October 2026 · Read-only system exploration and transaction inspection

The accepted design has two views: **07 — Topographic Atlas** for the whole-system bird's-eye view, and **05A — Precision Trace** for inspecting or demonstrating one transaction. The reference PNGs establish visual direction. They are not an executable application or a technically authoritative topology. Fixtures and normalized telemetry govern relationships, durations, and statuses when an illustrative image differs.

**P0** means required for the first usable handover implementation. **P1** means required for production readiness or the next increment. A demo can satisfy the demo-related criteria without satisfying live integration. Its release notes must state that distinction. These are requirements to validate, not claims that an application has already passed them.

## P0 — Core experience and evidence integrity

| ID | Scenario | Observable pass condition | Validation |
| --- | --- | --- | --- |
| P0-01 | Open the application with demo data. | The initial view is 07. Named system territories, group boundaries, important components, a directional selected route, and a visible source-mode badge are present. Components can be selected; this is not a PNG placed behind nonfunctional controls. | Manual interaction; smoke test loads fixture and selects an actual entity. |
| P0-02 | Navigate from 07 to a transaction in 05A, then return. | Selecting a trace opens 05A with that trace and the same environment and time window. Returning restores 07's filters, expanded groups, camera, and selected component or route. Opening a different trace deliberately replaces trace selection without resetting unrelated context. | End-to-end test with two environments and two traces; manual camera check. |
| P0-03 | Inspect the reference transaction. | The displayed reference request is `#7F2A`; its complete measured duration is `2.84 s` and its queue wait is `950 ms`, matching the fixture. Detail inspection exposes the full trace ID and relevant span IDs. Overlapping spans are not summed to invent end-to-end latency. | Data-level assertions plus inspector UI test. |
| P0-04 | Inspect 05A's spatial arrangement and scrub its replay. | Labels make clear whether an axis represents architecture layout or elapsed time. In architecture-layout mode, distance and camera position do not change any duration. The replay cursor, current operation, 3D highlighting, and 2D timeline derive from one playback time; pause and step settle on the same event or timestamp. | Deterministic clock test at span boundaries and mid-span; manual inspection. |
| P0-05 | Play, pause, seek, change speed, and restart. | Each control works. Playback speed is visible. Changing speed changes presentation time only. Seeking to the same timestamp produces the same visible state. At the end, the final status comes from evidence, and replay does not fabricate a new request. | Automated playback-state test and manual controls walkthrough. |
| P0-06 | Load a trace with parallel work, a retry, and an asynchronous link. | Parallel spans retain overlapping intervals. Retry attempts remain individually inspectable. Parent-child edges and span links are distinguishable. The asynchronous operation is not assigned an invented parent or forced into one synchronous call chain. | Fixture-based data assertions and focused screenshot review. |
| P0-07 | Follow request dispatch, response delivery, and streaming. | Direction and event type are distinguishable. Responses are only drawn as observed or explicitly inferred relationships; an identical reverse network path is never assumed. Streaming marks represent captured events or clearly labeled aggregate activity, not invented per-token events. Missing response evidence is stated. | Compare displayed events with fixture; manual legend review. |
| P0-08 | Inspect an incomplete trace or uninstrumented dependency. | Unknown, absent, sampled, pending, and error states remain distinct. Missing spans are visibly unresolved; no solid observed edge silently bridges the gap. A known configured dependency may remain visible with its separate declared styling. | Partial-trace fixture test; inspect status and edge legend. |
| P0-09 | Explore 07's hierarchy. | A group can expand, collapse, and be focused without losing stable component identity. Contours indicate grouping or containment, not unmeasured latency or load. Routine traffic and metric updates do not reposition the full map. Actual topology changes are identifiable. | Manual expand/collapse and update replay; position-stability assertion for unchanged entities. |
| P0-10 | Select services, edges, and spans. | Selection is consistent between scene, inspector, and 2D representation. Inspector content names the entity, operation, source, time context, and known status. Missing values read as unavailable rather than zero. Values have units and aggregation windows where relevant. | End-to-end selection tests; manual inspector review. |
| P0-11 | Inspect training lineage alongside inference. | Dataset version, training run, checkpoint, model version, and deployment are separately identified where supplied. The selected inference request links to its deployed model identity. Training lifecycle time is not placed on the request's millisecond axis or portrayed as executed within that request. | Lineage fixture assertions; manual view inspection. |
| P0-12 | Receive simulated incremental telemetry. | An unfinished operation has no fabricated completion time or success. Updates attach to existing IDs. Duplicate updates do not duplicate entities or events. Out-of-order updates are reconciled or flagged. Missing sequence ranges or stale watermarks are visible. | Adapter replay test with duplicate, late, missing, and reordered patches. |
| P0-13 | Switch among demo, replay, and live-capable UI states. | Source mode is continuously visible. A simulated feed is labeled demo even if animated in real time. Recorded replay states its recording window. Live is only shown when connected to a real configured adapter, with freshness and connection state; unavailable live functionality is honestly disabled or described. | Mode tests and release-note review. |
| P0-14 | Pause while updates arrive or lose the connection. | Pause freezes the investigation position while ingestion may continue. New-data availability is indicated; returning to latest is explicit. Disconnect/stale indicators appear without erasing the user's investigation. Reconnection reconciles state and exposes unresolved gaps. | Controlled incremental fixture and connection-state tests. |
| P0-15 | Use keyboard navigation or reduced motion. | Search, entity selection, inspector access, timeline stepping, view switching, and return navigation are available without a mouse. Focus is visible and is not trapped in the canvas. Reduced motion disables automatic camera travel and continuous decorative motion; underlying status and timing remain accessible. | Manual keyboard-only walkthrough; OS reduced-motion and in-app setting check. |
| P0-16 | Disable WebGL or use a constrained screen. | A readable 2D topology/trace alternative permits core search, selection, status inspection, and replay tasks. Errors are actionable. At widths below 1024 CSS px, the inspector becomes a drawer or stacked panel and the 2D alternative is offered prominently; controls do not cover the entire scene. | WebGL-disabled test and manual 390×844 / 1024×768 checks. |
| P0-17 | Inspect protected or sensitive telemetry. | The product remains read-only: no infrastructure restart, redeploy, mutation, or trade/action execution controls. Payload content appears only when actually supplied and authorized. Restricted payloads are redacted in scene, inspector, copy/export, and shared state. No raw credentials are put in URLs. | Inspect adapter operations; redaction fixtures and copy/share-state tests. |
| P0-18 | Compare the implementation with the accepted images. | 05A retains the dark spatial execution view, translucent stages, focused amber trace, restrained blue/violet context, inspector, and replay controls. 07 retains low-relief territories, contour boundaries, clear glyphs, and directional routes. Other rejected concepts do not become navigation modes or visual replacements. Text remains readable; bloom never hides a selected path or label. | Manual visual QA using both supplied references, not pixel-perfect text matching. |

## P1 — Integration, scale, and operational quality

| ID | Scenario | Observable pass condition | Validation |
| --- | --- | --- | --- |
| P1-01 | Connect an authorized real telemetry source. | One instrumented request can be found by its genuine trace ID and inspected in both views. Displayed spans and statuses match the source. Source timestamps, freshness, delayed export, sampling, and missing coverage are disclosed. A complete span arriving after completion is not presented as if observed while it ran. | Compare against source records; retain a sanitized validation trace. |
| P1-02 | Investigate cross-system timing uncertainty. | Known clock uncertainty or inconsistent ordering is flagged. The UI preserves recorded values and distinguishes inferred order from measured order. Critical-path or self-time metrics are shown only with a documented calculation and sufficient evidence; no double counting of overlapping work. | Synthetic skew/overlap fixtures and calculation tests. |
| P1-03 | Operate at realistic system size. | Grouping, progressive detail, label prioritization, and visible-edge limits preserve navigation and selected-trace access. All off-screen or aggregated entities remain searchable. No requirement to render every component and connection simultaneously. | Test with small and large fixture profiles; inspect search and aggregate counts. |
| P1-04 | Measure browser performance. | Record the benchmark environment and results described below. Quality reductions preserve selected paths, labels, input response, and evidence. The report distinguishes achieved results from unverified goals. | Browser profiling, frame timing, interaction measurements, and a retained report. |
| P1-05 | Bookmark or share an investigation. | Restoring a view preserves environment, time window, trace identity, view mode, filters, and relevant camera state. Permission checks apply when reopened. Tokens and raw payloads are excluded. Expired or unavailable traces receive a useful explanation. | Round-trip state test and unauthorized/expired-resource check. |
| P1-06 | Run a presenter-led transaction demo. | A deterministic replay can reset, advance by operation, pause on queue delay, inspect evidence, and return to 07. Optional camera-follow never overrides manual navigation without a visible control. The presenter can stop camera-follow immediately. | Rehearse the walkthrough twice; confirm identical replay results. |
| P1-07 | Compare a successful and delayed/failed transaction. | Comparisons disclose environment, model/version, and time context. Duration and state differences are grounded in the selected records. Visual emphasis is not presented as a proven root cause without evidence. | Controlled comparison fixtures and inspector review. |
| P1-08 | Exercise accessibility and rendering failure paths. | Color is reinforced by text, icons, line patterns, or shape. Text and controls meet the project's accessibility contrast target. Context loss, source errors, empty results, and denied access preserve navigation and explain the next available action. | Accessibility audit, context-loss simulation, and error-state walkthrough. |

## Visual QA checklist

Capture both views at **1440×900** and **1920×1080**, including overview, selected trace, open inspector, queue-delay focus, partial telemetry, and a paused replay. Record browser zoom and device-pixel ratio. Review at normal viewing size, not only as enlarged screenshots.

- Important labels do not overlap selected paths, disappear behind geometry, or extend outside the viewport.
- The inspector is legible without a large empty column obscuring the scene.
- The selected amber path is easy to follow against contextual blue/violet activity.
- Controls have clear hit targets, hover/focus states, and sensible disabled states.
- 07 has visible hierarchy and navigable territory boundaries; 05A has a clear selected execution and synchronized evidence.
- A selection survives view switching, camera movement, telemetry updates, and opening or closing the inspector.
- Reduced motion and the 2D fallback preserve the same facts and operations.
- At 1024×768 and 390×844, navigation and inspection remain possible through an adapted layout or the explicit 2D fallback. Full desktop 3D composition is not required at phone width.

## Provisional performance benchmark

These are proposed engineering targets, not tested claims or commitments to a specific hardware fleet. Before implementation sign-off, record **CPU, GPU, RAM, operating system, browser/version, viewport, device-pixel ratio, power mode, and rendering quality** for at least one reference laptop with an integrated GPU. Record a second environment if a more powerful GPU is needed to meet the visual target. Pin and retain the exact dataset used.

Use a small profile of roughly 25 components and a larger profile of roughly 1,000 components / 5,000 declared or observed edges, with collapsed groups and a representative selected trace. Add a controlled update stream. The large profile is a system-size target, not a requirement to display 5,000 animated edges.

Measure a 30-second scripted pan, selection, view transition, and replay sequence after warm-up. Proposed targets: approximately 60 fps in the small scene, at least 30 fps with aggregation on the large scene, and p95 visible input response below 200 ms. Report dropped frames, long tasks, and memory growth across repeated view switches. If targets fail, reduce secondary geometry, labels, and decorative effects before reducing trace correctness. Record any changed targets and the reason; do not silently claim a pass.

## Evidence required at handoff

Include a short validation record listing passed and unpassed criterion IDs, known limitations, test environment, fixture version, screenshots for both accepted views, and the commands used for meaningful automated checks. Mark live integration unverified until P1-01 is demonstrated. A mock screenshot, working animation, or green unit-test suite alone is not evidence that request tracing is accurate.
